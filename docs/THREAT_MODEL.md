# Threat Model

| Threat | Mitigation |
|---|---|
| Canonical state becomes a hidden executor or stale tracker authority | CANON-01/CANON-08/CANON-09 canonical state, dashboard, handoff, tracker-sync preview, and tracker-conflict report are read-only metadata. They do not execute tools, call providers, access personal data, start services, request approvals, mutate prompt trackers, write handoff files, auto-resume work, auto-overwrite trackers, or replace primary source-of-truth files. They only report JSON/Markdown metadata, a fixed hierarchy, conflict previews, handoff recommendations, tracker roles, migration phases, gateway/kernel status, and recovery hints; future mutation/recovery behavior must remain explicit, audited, policy-gated, and anchored to evidence. CANON-10 release gate validates the track as local-tested metadata/dry-run scaffolding only, not a live autonomous gateway or runtime replacement. |
| Durable execution records become a resume bypass or secret store | CANON-02 adds record contracts and read-only inspection only. Record schema requires risk, approval, ToolBroker-required, audit IDs, hashes, evidence paths, checkpoint IDs, rollback plans, and redacted args. HIGH/CRITICAL records require approval. The CLI does not resume, execute, write, or mutate records; future record writers/resumers must preserve ToolBroker, PolicyEngine, PermissionManager, ApprovalManager, and AuditLogger boundaries. |
| Agent Gateway becomes an external tool executor or self-approval surface | CANON-03 adds metadata contracts only. Gateway status confirms no server/listener starts, no tools are exposed externally, direct tool execution is not allowed, the gateway cannot approve actions, and policy/capability mutation is false. Request previews block direct tool execution and route HIGH/CRITICAL/approval-required requests to review. CLI remains the first frontend. |
| Recovery model silently resumes unsafe or approval-gated work | CANON-04 recovery preview is explicitly non-executing. It does not resume, mutate state, bypass approval gates, or reuse CRITICAL approvals. Prompt-pack recovery uses prompt tracker evidence, and recovery reports list unsafe actions to avoid. Future resume execution must remain separate, explicit, ToolBroker-routed where effects occur, policy checked, approval gated, and audited. |
| Code-mode/self-heal evidence is forged or misses a safety regression | CANON-05 artifact hashes are deterministic, redacted review metadata only and do not approve or execute patches. Safety lints conservatively block safe-only self-heal plans for audit, policy, ToolBroker, approval, personal-data, persistence, filesystem, redaction, package-install, live-provider, listener, secret-storage, and backup-restore weakening patterns. Future patch execution must still use ToolBroker, PolicyEngine, ApprovalManager, AuditLogger, tests, and human review. |
| Surface regression lane becomes an unattended command runner | CANON-06 surface lanes are metadata and dry-run only. The default run preview executes no commands, excludes personal-data and HIGH/CRITICAL lanes, and marks live provider checks opt-in. Dogfood suites are fixture-safe and require explicit user invocation. Future automatic lane execution must remain command-registry gated, safe-tier constrained, policy checked, and audited. |
| Performance scanner becomes a safety bypass by running arbitrary commands, profiling personal data, or recommending policy weakening | PERF-11 release gate validates local-first, bounded, non-mutating scanner behavior. Static scanners do not execute scanned code. Safe benchmarks reject HIGH/CRITICAL, personal-data, mutating, live-provider, paid-provider, background-service, and broad-refactor paths. Implemented commands route through ToolBroker, keep PolicyEngine final, preserve future ApprovalManager gates, audit scan/report/benchmark/profile/recommendation/baseline/patch-plan/dashboard actions, redact secrets, and treat recommendations/patch plans as review-only with `applied_patches=0`. |

## Assets

- User privacy and personal data.
- Workspace files.
- Credentials and secrets.
- Audit integrity.
- Policy and approval integrity.
- Model output quality.

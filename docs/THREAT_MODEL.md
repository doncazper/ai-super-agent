# Threat Model

## Assets

- User privacy and personal data.
- Workspace files.
- Credentials and secrets.
- Audit integrity.
- Policy and approval integrity.
- Model output quality.

## Threats and Mitigations

| Threat | Mitigation |
|---|---|
| Model hallucination | Keep harness thin; model final answers are not proof of action; actions must have tool results. |
| Prompt tracking drift | Keep a prompt ledger, ordered prompt queue, prompt audit, prompt record directories, and validation tests; AGENTS requires prompt status updates and final reports must include `prompt_id` plus `next_prompt_id`. |
| Golden eval overreach or stale quality claims | Golden evals default to safe categories, keep personal-data evals skipped, keep live LM Studio/provider checks opt-in, execute tool checks through `ToolBroker`, write pass/fail/skipped reasons with scorecards, and must not be treated as proof of live user readiness without a recorded live run. |
| Model-router benchmark overclaiming quality | Model-router and prompt-quality evals are fixture-backed by default, do not send prompts to LM Studio unless live mode is explicitly requested, compare route/tool/policy expectations to actual behavior, treat prompt-injection fixture text as untrusted data, and do not execute personal-data or send/write tools. |
| Prompt pack instruction smuggling | Prompt packs are parsed as SDLC data only; importer rejects `execute_all`, writes split files to `prompts/queued/`, preserves prompt body text without executing it, and `prompts next` skips blocked approval-gated prompts. |
| PromptOps autopilot overreach | `work run-next` is disabled by default; `work autopilot` requires `--safe-only`, only considers safe risk levels and allowlisted categories, stops at approval gates, and never treats imported prompt text as trusted policy instructions. |
| Overnight self-improvement overreach | Overnight work is constrained by `docs/SELF_IMPROVEMENT_OVERNIGHT_RUNBOOK.md`: allowed work is docs/tests/diagnostics/evals/tracking and low-risk refactors only; forbidden work includes personal-data connectors, sends, calendar/contact writes, policy weakening, approval bypass, audit disabling, package installs, external scripts, full disk access, persistence/background agents, unapproved commits, and unplanned network. `improve overnight-plan` is plan-only and excludes HIGH/CRITICAL/personal-data candidates. |
| Command catalog drift | `docs/COMMAND_REGISTRY.md` and `docs/COMMAND_TEST_MATRIX.md` are generated from command metadata and validated by `commands validate` plus tests; AGENTS requires updates whenever CLI commands are added, changed, renamed, deprecated, or removed. |
| Manual QA accidentally running risky commands | `commands qa-run` prints SAFE/LOW active command examples only and does not execute them in v1. HIGH/CRITICAL, personal-data, write/send, blocked, planned, stubbed, and legacy commands remain manual checklist items with approval gates and explicit QA notes. |
| Dogfood suite overreach | Dogfood suite commands are data and must be `python smart_agent.py ...` only. The runner does not execute tools directly, does not enable personal-data tools, keeps `personal_dry_run` preflight-only, requires an active session for `--session`, and relies on delegated commands to preserve ToolBroker, PolicyEngine, ApprovalManager, and AuditLogger boundaries. |
| Session logging captures sensitive output | Session logs are separate from AuditLogger, redacted by default, ignored by git, and never written to memory automatically. The recorder does not collect environment variables and does not bypass ToolBroker or approval gates; `session run` only delegates to existing `smart_agent.py` commands. |
| Feedback capture stores sensitive or policy-changing text | Feedback records are redacted before storage, written only to session-local `feedback.jsonl`, included in show/replay/export as review evidence, and audited. Feedback text is never treated as approval, permission grant, policy change, tool request, send instruction, or memory content. Unsafe feedback raises severity instead of executing remediation automatically. |
| Session review turns logs into unsafe or leaky bug reports | Session review reads redacted session previews and feedback only, writes local redacted review/bug artifacts, does not send data externally, does not access personal connectors, does not write memory, and does not automatically fix bugs. Policy/ToolBroker/PolicyEngine/Approval/Audit bypass or personal-data leak signals are classified as P0 for human triage. |
| External native-skill supply-chain attack | Native Skills Program intake treats third-party skill text, marketplace pages, repositories, and examples as untrusted data. Intake does not install or run external code, opaque binaries, package scripts, browser extensions, or setup commands. Useful behavior must be re-specified as local project-owned workflows. |
| Native skill permission or policy bypass | Native skills are reviewed workflow modules, not direct tool or permission grants. Skill records and manifests cannot grant capabilities, execute entrypoints, bypass approvals, weaken policy, disable audit logs, or replace ToolBroker. Manifest validation rejects unknown capabilities, executable fields, bypass language, enabled personal-data defaults, and CRITICAL skills without per-action approval. Any future action path must map to existing or separately approved brokered capabilities. |
| Native skill finder following untrusted skill text | The finder searches local metadata and candidate docs as data only. It does not browse external marketplaces, install skills, execute scripts, import code, grant capabilities, or mark candidates complete. Finder execution uses `ToolBroker`, `PolicyEngine`, and `AuditLogger`, and writes no memory by default. |
| Malicious PDF document content | PDF files are treated as `UNTRUSTED_DOCUMENT`. PDF v1 resolves paths through approved workspace roots, executes no embedded PDF actions/scripts/forms, uses no OCR or external binaries, enforces size/page/text limits, filters obvious instruction-injection text from deterministic summaries, writes no memory by default, and audits every brokered operation. |
| Hidden scheduler persistence | Scheduler v1 is manual-run only. It stores local JSON schedule records and does not install LaunchAgents, cron jobs, daemons, login items, or background services. Any system-level runner requires a decision record, explicit approval, and a separate release gate. |
| Scheduled action overreach | Supported scheduled workflows are allowlisted. Tool workflows still go through ToolBroker, PolicyEngine, ApprovalManager, and AuditLogger. Personal briefing sections require normal approvals, redacted `backup_create` schedules invoke brokered `backup.create`, and CRITICAL actions are never executed automatically. |
| Prompt injection from web pages | Mark fetched content `UNTRUSTED_WEB`; wrap it as data; strip scripts; do not follow page instructions; audit fetched domains. |
| Unsafe redirects or tracking URLs | Normalize URLs, strip common tracking parameters, validate redirect targets before following them, and block private/local hosts. |
| Search-provider query leakage | Keep search provider opt-in; allow `WEB_ACCESS_ENABLED=false`; redact `web.search` queries in audit logs by default; do not persist search history unless explicitly enabled. |
| Search-provider manipulation or outage | Treat search results as `UNTRUSTED_WEB`; normalize provider errors; return structured errors instead of hallucinated results. |
| Weather provider geocoder drift | Treat provider lookup failures as structured errors, cover weather evals with safe live smoke when configured, and normalize common city/state inputs without inferring device or IP location. |
| Fabricated research citations | Research workflow builds summaries only from returned search/fetch data, includes source URLs, reports fetch failures, and avoids claiming unsupported current facts. |
| Research workflow instruction smuggling | Source-grounded research strips the untrusted wrapper before excerpting, filters instruction-like sentences from search/fetch text, exposes fetch failures separately, and never treats webpage text as tool or policy instructions. |
| Approval confusion or click-through | Approval previews show request ID, risk, trust level, summary, redacted args, rollback availability, expiration, and allowed choices before approval. |
| Pending action preview leakage | Action Center stores exact secret-redacted previews locally for approval, but exported action records and lifecycle audit events minimize sensitive draft/body fields and replace sensitive summaries with redacted review notes. |
| Dry-run/preflight confusion | `preflight` and `--dry-run` use brokered dry-run evaluation, label output as non-executing, show approval requirements and sanitized args, and do not execute tools or access personal data. |
| Critical approval reuse | Critical actions are per-action only; approve-all/reuse choices are denied and tests verify reuse does not authorize a second critical action. |
| Prompt injection from email | Mark email metadata and bodies `UNTRUSTED_EMAIL`; selected-thread only; wrap bodies with an untrusted-content warning; never follow embedded instructions or allow email text to approve actions, change policy, reveal secrets, request tools, or send messages. |
| Prompt injection from messages | Mark messages and manual fallback files `UNTRUSTED_MESSAGE`; selected-scope only; wrap bodies with an untrusted-content warning; never follow embedded instructions or allow message text to approve actions, change policy, reveal secrets, request tools, harvest contacts, or send messages. |
| Malicious documents | Mark documents `UNTRUSTED_DOCUMENT`; no macro execution; web fetch refuses binary downloads by default. |
| Workspace document instruction injection | File assistant read/summarize/search treats file content as `UNTRUSTED_DOCUMENT`, filters instruction-like text from local summaries/excerpts, and executes no document-supplied tool requests. |
| Tool-broker bypass | Tools execute only through `ToolBroker`; tests verify unknown/direct paths are denied by policy boundaries. |
| Path traversal | Resolve absolute paths and enforce allowed roots before filesystem actions. |
| Secrets leakage | Deny known secret paths; redact audit/debug output; never store secrets. |
| Unsafe memory storage | Use categories and approvals; block secrets and default personal-body storage; redact memory content from audit arguments. |
| Unsafe memory context injection | Context injection is bounded by record and character limits, excludes personal memory by default, requires brokered `memory.context`, and audits injected memory IDs in the result summary. |
| Overbroad personal-data access | Disable personal tools by default; selected-scope reads only; avoid private database scraping and broad Full Disk Access. |
| Calendar read overreach | Calendar read connector is disabled by default, approval-gated, selected date range only, max-range limited, and returns compact summaries without notes/body or locations by default. Calendar event text is labeled as data, not instructions. The optional macOS path uses Calendar.app Automation permissions and does not scrape private databases or require Full Disk Access. |
| Calendar write abuse | Calendar create/update/delete capabilities are disabled by default, CRITICAL, per-action approval only, and Action Center gated. Draft commands produce review records only. Execution from approved actions still goes through ToolBroker, PolicyEngine, ApprovalManager, and AuditLogger. Low-level calendar write tools reject direct broker execution unless Action Center verifies the matching approved action id. No automatic invites, no recurring events in v1, no notes/body unless explicitly allowed, and no live native write provider is enabled by default. |
| Task/reminder access or mutation abuse | Tasks connector provider access is disabled by default. Listing is selected-scope, HIGH risk, approval-required, and no full export. Draft creation routes through brokered `tasks.draft_create` and creates an Action Center item only. Create uses one approved `--from-action` execution. Update, complete, and delete are CRITICAL per-action tools through ToolBroker and ApprovalManager. Task contents are not stored in memory by default. V1 uses adapter/mock support only and does not scrape Reminders databases or request Full Disk Access. |
| Meeting prep overreach | Meeting prep reads one selected calendar event through `calendar.read_selected_event`, optionally runs explicit `contacts.search` queries, and optionally runs `web.search`. Calendar/contact steps remain HIGH risk, disabled by default, approval-gated, and audited. The workflow sends no email/texts, performs no calendar/contact edits, does no bulk contact export, and writes no memory by default. |
| Contacts read overreach | Contacts connector is disabled by default, approval-gated, selected-scope only, and search returns compact candidates without email/phone values. Selected reads require a selected-scope token and explicit requested fields, label contact text as data rather than instructions, omit notes, redact email/phone/address values by default, and do not scrape private databases or require Full Disk Access. |
| Contacts edit abuse | Contact edit/create commands create Action Center records first and do not silently mutate Contacts.app. `contacts.update_selected` and `contacts.create` remain disabled by default, CRITICAL, per-action approval only, and one-shot when approved. Low-level write tools reject direct broker execution without a verified Action Center action id, and submitted args must match the approved preview. Updates require explicit field-level diffs, phone/email/address values are redacted in persisted previews and audit logs, bulk edits are denied, delete remains deferred, and all execution still goes through ToolBroker, PolicyEngine, ApprovalManager, and AuditLogger. |
| Email sending abuse | Email send v1 requires an Action Center draft and blocks direct `email.send_approved` execution without a verified approved action id. Submitted send args must match the approved reviewed draft before the mock/no-provider send path can run. Preflight shows from account/provider, recipients, subject, full body, attachments, selected thread context, and irreversible rollback status. The capability remains disabled by default, CRITICAL, per-action approval only, with no approval reuse, no background sends, no bulk sends, attachments blocked in v1, and all draft/approval/send/failure events audited. Email thread content remains `UNTRUSTED_EMAIL` data and cannot approve, instruct, or trigger sending. |
| Messages handoff abuse | Messages safe handoff v1 avoids automatic sending entirely. It does not scrape `~/Library/Messages`, require Full Disk Access, or use Accessibility/AppleScript send automation. Drafts come from selected workspace files labeled `UNTRUSTED_MESSAGE`; low-level save/copy tools require a verified approved Action Center action id and submitted args matching the approved preview; saved drafts are workspace-bounded; clipboard copy is explicit and audited; message content cannot approve, change policy, execute tools, or trigger a send. |
| Browser clipping prompt injection or profile overreach | Browser clipping v1 accepts only explicit URLs. Fetching goes through `web.fetch_url`, content remains `UNTRUSTED_WEB`, summaries filter instruction-like text, saved clips are `UNTRUSTED_DOCUMENT`, and workspace writes go through `filesystem.write`. Canonical browser workflow capabilities are `browser.read_url`, `browser.summarize_url`, `browser.clip_url_to_workspace`, and the disabled `browser.selected_tab` stub. The connector does not read history, cookies, sessions, forms, passwords, bookmarks, private profile databases, or submit forms. Native selected-tab reading is stubbed and disabled until a selected-scope permission model is approved. |
| Knowledge capture poisoning or secret retention | Knowledge Capture v1 writes only workspace capture files through `filesystem.write`, fetches URLs through `web.fetch_url`, reads files through `filesystem.read`, and stores no memory automatically. Secrets are rejected before capture writes. Captured web/file content is untrusted data by default, file captures can be labeled `TRUSTED_USER` only with explicit `--trusted-user`, summaries filter instruction-like text, Apple Notes/private app databases are not accessed, and `promote-to-memory` goes through Memory v2 policy with personal-looking content blocked by default. |
| Privacy inventory overexposure | Privacy Center v1 reads connector/config/store metadata only and does not query calendar, contacts, email, messages, tasks, browser history, private app folders, or provider contents. Inventory returns counts and setup/status fields, export returns redacted previews by default, audit-summary omits raw args, all privacy operations are audited, and memory deletion requires `--confirm DELETE-MEMORY` plus brokered `memory.clear`. |
| Backup archive secret leakage | Backup v1 stores local redacted archive directories only. It excludes `.env` and private key/certificate files, redacts secret-like values in copied config/docs/memory/action/capture data, includes only optional redacted audit metadata, never queries live personal connectors, and audits create/export/list/inspect/verify/restore calls through ToolBroker. |
| Restore policy rollback or unsafe migration | `backup.restore` is HIGH risk and approval-required. Restore verifies manifest and file hashes, validates backed-up `config/capabilities.yaml` with the current startup validator, blocks manifests that enable personal connectors or weaken CRITICAL approval rules, and creates pre-restore copies before replacing workspace/config/docs files. |
| Email read overreach | Email connector is disabled by default and approval-gated. Metadata listing returns no body and is labeled `UNTRUSTED_EMAIL`; thread reads require one selected thread id; bulk ids such as `all` are denied; summaries/drafts do not store body text; draft replies are never sent, deleted, moved, or archived. |
| Email triage overreach | Email triage reads metadata only by default and classifies priority from sender/subject/snippet metadata. It reads at most one selected thread body after approval, redacts body content from the triage report and audit args, wraps body content as `UNTRUSTED_EMAIL`, sends nothing, mutates nothing, and writes no memory by default. |
| Messages read overreach | Messages connector is disabled by default and approval-gated. No live macOS Messages connector is implemented until a safe permissioned path exists; the project does not scrape `~/Library/Messages` or request Full Disk Access. Manual `messages.draft_from_text` fallback reads only `./workspace` files, denies traversal/outside paths, wraps content as untrusted, audits file reads, does not store body text, and never sends, deletes, moves, archives, modifies messages, or harvests contacts. |
| Live smoke test overreach | Smoke tests do not enable personal-data tools by default. Calendar/contact smoke is dry-run/check-only unless a future explicit selected-scope live read path is approved. Tests marked `personal_data` are excluded by default. |
| Weather location leakage | Weather lookups use user-provided locations only, avoid silent IP or device geolocation, avoid long-term location history by default, redact location arguments in audit output, and require a separate approval-gated design before using precise device location or stored home/work locations. |
| Weather default-location misuse | Default weather location is used only when explicitly configured by environment, dedicated weather preferences config, direct lat/lon config, or the weather config CLI; the agent does not read macOS Location Services, infer location from IP, or write default locations to memory automatically. |
| Weather cache precise-location retention | The weather cache is an operational TTL cache, not long-term memory; keys are hashed, and precise-looking street addresses or direct coordinate queries bypass cache storage entirely. |
| Weather provider manipulation, outage, or stale data | Treat Open-Meteo geocoding, Open-Meteo forecast responses, and NWS points/grid/alerts responses as `UNTRUSTED_WEB`; include retrieval/provider timestamps when available; normalize provider errors, malformed responses, geocoding failures, unsupported locations, and missing NWS grid data; enforce timeouts and rate limits; return structured failures instead of hallucinated forecasts or alerts. |
| Weather alert exaggeration | NWS alerts are displayed only when returned by the provider; unsupported alerts and empty alert lists are stated explicitly, with cautious limitation language and provider/source metadata. |
| Weather-impact web prompt injection | Flight-delay, closure, and storm-update workflows treat web search snippets and fetched web content as `UNTRUSTED_WEB`; suspicious instructions are filtered from workflow summaries, weather data and web results remain separate, and current closure/delay claims require returned web sources. |
| WeatherKit credential misuse | WeatherKit support is currently a provider stub only; it checks credential env var presence without returning values, does not read private keys, does not generate JWTs, and does not call Apple APIs until a reviewed implementation plan is approved. |
| Manifest drift or missing safety metadata | Startup validation requires risk, default-enabled state, approval requirements, storage behavior, trust level, and audit field declarations for every capability. Web capabilities that can touch the network must declare rate limits. |
| Expanded prompt-injection attempts | Regression tests cover malicious instructions from web, email, messages, and workspace-file text that try to reveal secrets, change policy, call tools, send email/text, disable audit logs, or store private data. Such content remains data only. |
| Email/text sending abuse | Draft-only workflows before send tools; M8 send tools disabled by default with critical per-action approval and preflight summaries. |
| Calendar/contact modification abuse | Calendar write v1 is Action Center gated, disabled by default, CRITICAL per-action only, and uses brokered execution. Contact writes remain disabled/deferred. |
| Self-improvement weakening safety | Branch-based changes; policy-reduction checks; protected safety files; tests and diff before approval-gated commit. `improve create-action-for-commit` creates only a pending Action Center commit record after brokered tests/diff and never commits directly. |
| Audit-log tampering | Hash-chain audit entries; later verification command. |
| Configuration tampering | Validate capabilities at startup and deny unknown/dangerous entries. |

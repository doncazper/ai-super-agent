# Generated Artifact Hygiene

Date: 2026-05-25

Prompt: `CONTINUE-RELEASE-HARDENING-CLEAN-BOUNDARY`

## Scope

This document classifies local generated artifacts that can make the release working tree look dirtier than the reviewed source changes. It is a release-boundary aid only. It does not change runtime behavior, retention policy, provider behavior, ToolBroker routing, PolicyEngine gates, ApprovalManager requirements, or AuditLogger behavior.

## Non-Goals

- Do not delete source-of-truth details.
- Do not delete generated artifacts automatically.
- Do not hide release blockers or validation failures.
- Do not ignore source fixtures, docs, tests, prompts, or command metadata.
- Do not treat ignored local artifacts as proof that a feature is release-ready.

## Reviewable Fixtures

These workspace paths are intentionally not ignored by this pass because they are source fixtures or static dogfood material:

- `workspace/dogfood/`
- `workspace/skills/`
- `eval_cases/`
- `dogfood_suites/`
- `tests/`
- `docs/`
- `prompts/completed/`, `prompts/queued/`, and `prompts/packs/`

If one of these starts carrying generated runtime output, add a targeted ignore rule or move the generated output instead of ignoring the whole directory.

## Release Boundary Procedure

1. Run `git status --short --ignored` and review ignored generated outputs separately from source changes.
2. Confirm `.gitignore` covers only local generated artifacts, not docs/tests/source fixtures.
3. Do not use destructive cleanup commands without explicit user approval.
4. If cleanup is desired, remove only generated local artifacts after confirming they are not needed as evidence.
5. Keep release evidence in docs or sanitized fixtures, not in raw local generated workspace files.
6. Run targeted artifact-hygiene tests and the feasible release validation set after changing ignore rules.

# Apple Ecosystem Architecture Decision

Status: accepted for planning

Date: 2026-05-23

## Context

The project will eventually integrate with Apple Calendar, Reminders, Contacts, Mail, Messages, and business lead-response channels. These connectors touch local private data and can create irreversible side effects, so the architecture must be explicit before new runtime work begins.

This decision record is planning-only. It does not enable any connector, read any personal data, send any message, write any calendar/contact/task data, or change policy.

## Decision

Apple ecosystem integrations must use selected-scope, permissioned, brokered paths. Every runtime action must continue through ToolBroker, PolicyEngine, PermissionManager, ApprovalManager, and AuditLogger. Native bridge code may be considered only when it can preserve selected scope, redaction, auditability, and per-action approval.

## Architecture Rules

1. Calendar and Reminders should use EventKit or a permissioned native bridge when a real provider is approved.
2. Contacts must use selected-scope access only and must not perform bulk export by default.
3. Gmail, Mail, and email-like sources remain metadata-first, read-selected, and draft-first before any send path.
4. Consumer iMessage and personal Messages do not currently have a general safe first-class inbox/send API in this project.
5. Messages start with draft, handoff, and manual selected text workflows.
6. Private Messages database scraping is not an acceptable first approach.
7. Broad Full Disk Access is not an acceptable first approach.
8. Apple Messages for Business is the preferred long-term business lead-response path.
9. All sends are CRITICAL and require per-action approval unless a future explicit auto-response policy is separately designed, reviewed, tested, and approved.
10. Lead response must be channel-agnostic through the LeadInbox abstraction.

## Component Direction

| Area | Preferred path | Forbidden or deferred path |
|---|---|---|
| Calendar | EventKit or permissioned native bridge, selected date/event scope | Full calendar export, private database scraping, silent writes |
| Reminders / Tasks | EventKit reminders or permissioned native bridge, selected list/task scope | Private database scraping, background task mutation |
| Contacts | Contacts framework/native bridge with selected records and explicit fields | Bulk export, private AddressBook database access, silent edits |
| Mail / Gmail | Metadata, read-selected thread, draft-only, then approved-send only | Full mailbox ingestion, unreviewed send, private Mail database scraping |
| Messages / iMessage | Manual selected text, workspace context file, draft/handoff | Messages DB scraping, Full Disk Access, AppleScript/Accessibility auto-send |
| Apple Messages for Business | Official business channel strategy through LeadInbox | Consumer iMessage as business lead automation |
| Telegram / Gmail lead sources | Config doctors first, lead-source adapters later | Reads/sends by key presence, hidden inbox polling |

## Trust And Risk

| Data / action | Trust label | Risk |
|---|---|---|
| Apple personal calendar/contact/task metadata | LOCAL_PRIVATE_DATA | HIGH |
| Email/message bodies | UNTRUSTED_EMAIL / UNTRUSTED_MESSAGE | HIGH |
| Draft responses generated by the model | MODEL_OUTPUT | HIGH until reviewed |
| Any send action | MODEL_OUTPUT plus channel data | CRITICAL |
| LeadInbox metadata | LOCAL_PRIVATE_DATA or UNTRUSTED_WEB depending source | HIGH by default |

## Required Gates

- Personal connectors disabled by default.
- HIGH reads require approval.
- CRITICAL sends/writes require exact per-action approval with no approval reuse.
- ToolBroker remains the only execution path.
- Audit logs must cover denials, approvals, executions, failures, and handoffs.
- No memory storage of personal lead content by default.
- Untrusted email/message/web content cannot instruct the agent to execute tools, change policy, reveal secrets, or approve actions.

## Why This Is Optional And Phased

Apple ecosystem access is high value, but the privacy and side-effect risk is high. The project already has safe draft-only and mock/provider-stub patterns. Future Apple work should proceed through decision records, selected-scope adapters, mocked tests, dry-runs, and release gates before live personal data is read or any write/send is enabled.
